# Contributing

PRs are welcome. Describe the problem, the change and what you tested. Keep hardware-specific changes reversible, and keep credentials, local addresses and personal screenshots out of commits.

## Source locations

- `src/com.spinoff.lumahome/`: LG launcher and shared UI code.
- `tools/`: native LG runtime helpers. The copies under `src/.../runtime/` are generated by `build.py`.
- `custom_components/luma_home/`: Home Assistant integration; its frontend card is mirrored at `ha/luma-home-card.js`.
- `android-native/`: current native Streamer preview. `android/` is the earlier web-based implementation.
- `peer/`: direct-pairing prototype. It is not installed or used by the current preview.

`build.py` copies shared launcher files into the overlay before packaging. Change the source file, then rebuild; do not edit the generated runtime/overlay copies independently.

## Checks

- Python: `python3 -m unittest discover -s tests -p 'test_*.py'`.
- JavaScript: run each `tests/*.cjs` file except the `_`-prefixed helpers with Node. Browser tests require Playwright and Chrome; `PLAYWRIGHT_PATH` and `CHROME_PATH` can select local installations. The peer tests also need OpenSSL and a loopback listener.
- Android: in `android-native/`, run `./gradlew --no-daemon testReleaseUnitTest lintRelease assembleRelease` with JDK 17+ and the Android SDK installed.
- webOS packages: `python3 build.py`. `SOURCE_DATE_EPOCH` sets package timestamps; the default is zero. Packages exclude hidden files, bytecode, backups and symlinks.

Automated key injection does not prove that physical Home/mic gestures work. Test both remotes, both HDMI inputs, input changes while panels are open, sleep/wake and standalone fallback on hardware before calling those behaviors verified.

The current APK is a development preview. Retain its signing identity for preview updates; plan production signing and migration before a stable release rather than requiring users to uninstall and lose settings.
